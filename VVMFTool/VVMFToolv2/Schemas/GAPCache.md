# Managed GAP cache

The configured `CacheDirectory` contains a package-owned `.vvmf-cache.json` admission index and immutable `entry-<UUID>` directories. Each entry owns exactly `result.json`, `state.wsp` and `manifest.json`. Unindexed files are outside cache cleanup. A path or hash in a portable mathematical snapshot does not register a workspace for execution.

The version-1 index records `Kind = "VVMFToolGAPCache"`, a store `CacheID`, and an `Entries` association. Each entry records its runtime fingerprint, the SHA256 and byte length of each fixed artifact, integer creation/last-use timestamps in milliseconds since Wolfram's epoch, a `Leases` association, and `PendingEviction`. The index is local package state and is written only after copying a previously verified native checkpoint pair. The mathematical export ledger is independent of this evictable index.

An entry may additionally carry a `Resume` record when it holds the verified `BaseReady` or `Partial` state of a failed build: its `Key` (SHA256 of the canonical construction record and requested S/T words), `StateID`, `GeneratorIdentity`, `StateGeneration`, `Status` and `Claim`. `Claim` is `null` or the claiming kernel's `Token`, `PID`, `Host` and `Started`. A later build with the same key claims the entry under the index lock; a claim whose local owner no longer exists may be reclaimed. Consuming the claim removes the `Resume` record, leaving an ordinary evictable entry. Complete states are never marked resumable. Indexes without the field remain valid.

Publication copies and checks artifacts outside the index lock, writes a manifest naming the copied paths, and atomically inserts the complete entry into the index. A failed or cancelled copy removes its owned unpublished directory. Publication leaves the source checkpoint intact. No arbitrary imported manifest can insert an entry.

Admission uses the currently configured canonical root and matching cache/entry identities. It acquires a durable lease before reading workspace bytes, checks all artifact hashes against the local index, validates the exact mathematical envelope and paired manifest, and checks the executable/adapter/build/package fingerprint before issuing a private checkpoint reference. GAP still independently reexports restored native data before further computation. Changing `CacheDirectory` does not erase the preceding directory, but its references cannot be admitted until that directory is configured again.

A lease records a unique token, host, PID and kernel start identity. Storage transactions use an exclusive `.vvmf-lock` directory with a separately owned nonce. A lock with an unknown/interrupted owner is reported as busy rather than deleted by inference. Cleanup prunes leases only when the owning local process/start identity demonstrably no longer exists. Remote-host leases and failed process inspection remain protected. A shared filesystem's directory creation and atomic rename must be coherent for cross-kernel exclusion; asynchronous cloud synchronization is not a distributed locking service.

`CleanGAPCache` accounts for the actual bytes of indexed artifacts and selects entries by last successful use, with entry ID breaking timestamp ties. It publishes eviction intent before deleting, so new readers cannot enter those entries. An active entry is reported as deferred; other eligible entries may be removed to meet the cap. The final reader's release completes pending eviction. Entry content conflicts and filesystem failures are reported, and surviving indexed files can be retried. Cache cleanup never modifies an in-memory group's mathematical data.

All internal paths are canonical and checked for symlink components, including dangling links. Entry cleanup deletes only fixed owned files and an empty directory; unexpected files preserve the entry. This controls package ownership, not hostile concurrent changes by someone with write access to the local package store.

Temporary call storage is separate. A private call record owns its unique directory, exact launched worker tokens and admitted source leases. Completion, failure, cancellation and thrown exits release those resources. Persistent copies survive temporary cleanup. No source lease is released until the call's workers have stopped. Successful native restoration advances persistent last-use time even if later requested work fails.
